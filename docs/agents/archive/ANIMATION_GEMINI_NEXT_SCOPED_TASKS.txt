G1 ONLY: DEVICE-FREE ANIMATION DOCUMENT MODELS

Implement the model/persistence/history portion of G1, with meaningful CPU tests. Foundation review corrections have already been implemented by Codex; do not recreate them. No Editor window or rendered preview is requested.

1. Reuse AnimationClipDefinition, AnimatorControllerDefinition, AnimationAssetCodec and FileSystem/VFS. Create clip and controller document models in an appropriate existing CPU authoring location/target (suggested names: AnimationEditorDocument and AnimatorEditorDocument). Model code must not use ImGui, Window, Scene, renderer/device services or a VFX document as its data authority. Follow existing module dependencies; avoid a general framework rewrite.

2. A document owns a working value definition, file path, stable selection, unique current revision token and saved revision token. Imported/shared resources and scene simulation do not own or reset the document. Never expose uncontrolled mutable references that bypass history/validation. Edits must retain IDs, unknown-to-UI authored values and the existing complete resource references/fallbacks.

3. Implement transactional edits: Begin -> update validated working candidate -> Commit once, or Cancel restoring content, selection and revision. Invalid edits and semantic no-ops add no history and do not change dirty state. Support Undo/Redo with bounded command count AND a documented memory budget for nested snapshots. Reject/handle oversized commands explicitly. Do not identify dirty state by stack depth: Save -> edit -> Undo -> branch at the same depth must get a new unique revision. Undo back to the saved revision is clean; Redo away is dirty. Saving does not silently erase useful history.

4. New/Open/Close/Reload must guard dirty data through a concrete pending operation and Save/Discard/Cancel response. Implement the pure state/API contract; do not display dialogs. Failed reads, wrong asset kinds, malformed files, validation errors or failed saves preserve the current document, path, history, selection and saved marker. A failed save must not execute the pending destructive operation. Stale responses must not discard newer edits. SaveAs changes path and marks the exact saved revision only after successful atomic file replacement.

5. Use stable authored IDs for controller state/parameter/transition selection, and stable bone/track identity for clip document selection. Reordering must not redirect selection to another vector element. Removing a selected item clears or deterministically repairs selection; history restores before/after selection. Do not implement G3 keyframe widgets or invent a full key-ID/schema migration in G1. Build only the selection/edit model needed for these tests.

6. Add permanent always-active tests through the existing device-free Animation test target (or a justified equally device-free authoring target):
   - Clip/controller Open -> valid edit -> SaveAs -> actual file parse/reopen preserves authored data and IDs.
   - Source-definition and document-copy isolation; two documents do not share mutable draft state.
   - Save/edit/Undo/Redo and branch-at-same-depth revision identity.
   - No-op, invalid edit, transaction cancel and one-history-entry commit.
   - Deterministic history limits and oversized edit behavior.
   - Guarded New/Open/Close/Reload: Save/Discard/Cancel, invalid target, stale response and failed-save preservation.
   - Selection survives reorder and repairs delete, including Undo/Redo restoration.
   - Actual malformed/missing/VFS/wrong-kind inputs and atomic save failure preserve last-good state; tests must not mirror a test-only implementation.
   - No window, device, shader compilation, scene update or hardcoded demo rig/effect is needed.
