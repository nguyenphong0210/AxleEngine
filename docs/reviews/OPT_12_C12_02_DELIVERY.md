The user directly assigned C12-02 to Codex after the C12-01 delivery. Preserve

package lowers validated graph documents to HLSL and invokes the existing DXC
backend for real DXIL and SPIR-V bytecode. It includes bounded physical GPU

## Architecture and public APIs

- `Asset/MaterialGraphHLSL.hpp`: `MaterialGraphHLSL::Lower` first validates a
  document using its explicit `MaterialNodeRegistry`, then looks up lowering
  callbacks in a separate `MaterialHLSLRegistry`. The Asset module still links
  Core only. No RHI, Renderer or Editor dependency was added.
- `Asset/BuiltinMaterialLowerings.cpp`: registrations for InputUV, ParameterRef,
  Multiply, Lerp, SampleTexture2D and PBRMasterOutput. The generic compiler does
  not branch on node-type names. Additional trusted node/lowering registrations
  work without changes to central graph/compiler dispatch.
- `Renderer/MaterialSurfaceShader.hpp`: assembles standalone shader source from
  generated declarations and a surface-evaluation function. The template and
  shared BRDF library are embedded by CMake; generated graph shaders do not
  require runtime disk includes.
- `Scene/MaterialGraphProgram.hpp`: `MaterialGraphProgram::Compile` composes the
  CPU lowerer, Renderer template and existing `RHIShaderCompiler`. It returns
  both stage bytecodes, merged reflection, generated HLSL/resource metadata and
  default property values. No graphics device is required for compilation.

Node definitions and emitter revisions must match. Lowerings are explicitly
owned, trusted synchronous callbacks; their code/modules and captures must stay
alive through a call. There is no plugin DLL registration/unload integration in
this package. Unknown/mismatched lowerings, malformed outputs, invalid graph
inputs, callback failures/exceptions, unsupported formats and DXC failures return
diagnostics without replacing the previous output artifact. Node diagnostics
retain original document locations; DXC virtual source names use numeric node
IDs and map errors back to authored nodes.

Used parameters become uniform symbols `mg_pN`, with an explicit authored-name
mapping and typed defaults. Texture/sampler symbols and node temporaries are also
generated by the compiler. Authored parameter names never become identifiers or
source directives. Defaults on unconnected pins become typed literals; incoming
connections take precedence. Scalar splats explicitly repeat components for
HLSL 2021. Dead nodes/resources are omitted from compiler output while the authored
document remains intact. Layout/name/order-only edits preserve emitted source.
Parameter-default changes update metadata without baking values into shaders.
The CPU semantic key includes lowering revisions and is not a C12-03 pipeline
cache key or a frozen parameter-instance ABI.

Only explicit DXIL and SPIR-V targets are accepted. DXBC is rejected; no automatic
OpenGL graph backend or fallback is claimed. Basic reflected-interface/binding
compatibility is checked with existing production helpers. Full cross-backend
layout/reload/cache acceptance remains C12-03. Render states such as culling and
depth-write remain authored document/caller pipeline state, not shader code.

## Surface and supported resource baseline

The standalone surface template consumes BaseColor, Metallic, Roughness,
tangent-space Normal, Emission and AO for DefaultLit/Opaque. It uses the same
GGX/Smith/Schlick BRDF functions as ForwardPBR, now factored into
`PBRCommon.hlsli`. The existing ForwardPBR keeps its broader light/IBL/material
features; the graph template is a bounded one-directional-light plus simple
ambient baseline. Graph IBL, multi-light/shadow integration, transparent surfaces
and later lighting packages are not accepted by this compiler slice.

The supported raw-image contract is explicit:

1. Source declarations carry `TextureColorSpace(sRGB|Linear)` and
   `TextureSampler(symbol, LinearRepeat)` annotations. Bridge default descriptors
   carry equivalent typed metadata.
2. Shader-property reflection preserves this metadata. Binding plans select
   hardware sRGB or linear views and associate actual reflected sampler bindings.
3. Scene rendering uses a dedicated trilinear/repeat/anisotropy-1 sampler for
   explicit LinearRepeat. Unannotated custom shaders retain the existing default
   sampler behavior. Missing explicit sampler associations fail plan validation.
4. sRGB decoding occurs in the hardware texture view before filtering; shader
   code does not apply another decode afterward. Alpha remains linear.

Other authored sampler modes currently fail lowering with `MG_HLSL_SAMPLER`,
rather than silently using the baseline sampler. Texture existence/import
descriptor overrides, fallback/dependency diagnostics, broader sampler policies,
mip-quality policy and automatic product graph-resource loading remain C12-04.
No per-asset sidecars or authored root registry were added.
